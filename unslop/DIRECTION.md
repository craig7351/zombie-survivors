# 殭屍大逃殺 v2.0 — unslop 方向（待小關確認）

> unslop by Damir Sokolovsky ([@heydamir](https://x.com/heydamir)), CC BY 4.0。

## 五行方向

- **Product.** 給想用手機或筆電偷玩十分鐘的人，一款瀏覽器直接開、免安裝、操控只有走位的 3D 殭屍倖存者遊戲；打贏 7 隻殭屍王算通關，也有無盡死鬥可以刷波數。
- **Character.** 髒、緊繃、末日求生。**不是** 乾淨、可愛、賽博。
- **World.** 廢墟與警戒線——混凝土、鐵皮、生鏽、警示條紋、屍體腐敗的黃綠、隨時會熄的日光燈。世界的顏色來自**腐敗綠 + 工業橙 + 警戒紅**，但它們只出現在「該亮」的東西上（血條、當前目標、王出現），不染色介面本身。
- **Moments.** ① **實機遊戲畫面**當 hero 視覺——真的殭屍潮、真的彈道、真的低多邊形角色，不是漸層色塊；玩家一眼知道自己在玩什麼。② **王血條**是全站唯一的高潮時刻：紅色實心條 + 警戒條紋 + 名字橫排，是「看這裡」的訊號。③ **在線人數走勢圖**（已存在）升級成有手感的單色長條圖，一眼看出這站活著。
- **Signature.** **一條 4px 的警戒條紋**（黑黃斜紋）——出現在王血條邊緣、難度卡選取處、破關畫面。像工地圍條，是這個產品專屬的記號，全站只用這一個。

## 設計系統（這是重點，不是逐頁微調）

同一套 slop 語彙被寫進 19 個 component，所以先立系統：

| 面向 | 現況 | 目標 |
|---|---|---|
| 表面 | `bg-black/40 + backdrop-blur-md` × 60+ | **單一中性階梯**，深色偏廢墟灰（`#0d0f0c` → `#161a15` → `#1e231c` → `#272d24`），髮絲線 8%，深色主題靠階梯與髮絲線給深度，**零 backdrop-blur** |
| Accent | 綠/琥珀/玫瑰/萊姆同時為主 | **一個 accent：警戒橙 `#ff7a1a`**（工業感，來自世界）。語意色另外兩支且低調：負 `#e5484d`、正 `#4cc38a` |
| 文字角色 | 十種半透明白 | **三階**：primary `#ecefe6` / secondary `#a3a89b` / muted `#6f7466` |
| 字重 | 900 為主 | **400 與 500 為主**，600 僅限極少數強調；無 700+ |
| 字級 | 任意值（0.26em/0.6rem/0.66rem/0.72rem） | **固定階梯**：12/13/14/16/20/28/40/56 |
| 圓角 | 全 `rounded-full` | **按尺寸分級**：控制 8、卡片 12、面板 16；巢狀半徑 = 外半徑 − padding |
| 圖示 | 148 處 emoji、67 種 | **一套 lucide 線性圖示**，18px、stroke 1.5、統一 muted 色；**全站 emoji 清零**（含 changelog 與難度/角色資料） |
| 間距 | 1.5/2/3/4/5/6 混用 | **4px 階梯**：4/8/12/16/24/32/48 |
| 動態 | 彈簧 hover、animate-ping、漂浮多邊形、動畫 width | **單一曲線** `cubic-bezier(0.22,1,0.36,1)`、120–180ms；只保留「有意義」的動態（在線狀態點改為靜態小點 + 文字「現在有 N 人在玩」）；**移除漂浮多邊形** |

## 九個 pass 的執行順序

1. **間距** → 2. **顏色** → 3. **圖示** → 4. **文案** → 5. **字體** → 6. **版面** → 7. **細節** → 8. **視覺** → 9. **動態**

## 版面關鍵決策（不做就不算完成）

- **首頁改成分欄**：左側文字（標題 + 一句話 + 暱稱 + 開始），右側**實機遊戲畫面**（`unslop/gameplay-1~3.png` 已備妥），不再置中堆疊。
- **首頁按鈕收斂**：一主（開始遊戲）＋ 一次要（排行榜）。其餘（圖鑑、留言板、線上人數）降為文字連結或移進遊戲內選單。
- **首頁四張統計卡**：改為不等寬節奏——一個主要數字（同時在線最高／場次）+ 三個小字。移除 emoji。
- **資料層清 emoji**：`characters.ts` 12 處、`difficulty.ts` 5 處、`upgrades.ts` 27 處、`deathmatch.ts` 8 處、`changelog.ts` 8 處、`meta.ts` 5 處、`game.ts` 22 處 → 改為圖示代碼（字串 key + lucide 名稱）。

## 待小關裁示的三件事

1. **範圍**：19 個 component 全站改（工作量大但根治），還是先只做「首頁 + 遊戲內 HUD」兩個畫面驗證方向，其餘頁面下一輪？
2. **hero 視覺**：直接用**實機截圖**（真、真實、零生成成本，但會隨遊戲更新而過期），還是用 image_generate 畫一張「廢墟場景」風格化 hero（可控、好看，但不如截圖真實）？我傾向**實機截圖 + 疊一點廢墟色調**，因為這是本產品能有的畫面。
3. **emoji 資料層**：升級／角色／難度的 emoji 同時出現在 UI 與 3D 預覽載入佔位。改成 lucide 圖示會讓「角色卡」失去一點辨識度——是否接受以「顏色標記 + 圖示」取代？
